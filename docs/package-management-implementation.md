## Unified model decisions

1. Extend existing CMS package identity and draft item tables, not a competing package store. Add explicit variants, eligibility, immutable publication revisions, activity, and seed provenance.
2. A working draft and a published revision are separate. Editing does not change the active publication. Revision-aware atomic save rejects stale edits. Publish validates and snapshots a complete definition; unpublish/archive only affects future use.
3. A single full-package variant is the default. Good/Better/Best variants exist only when an administrator explicitly creates them; never derive partial discounted offers from a fixed-price package.
4. Catalog prices are not overwritten. Catalog, percentage, fixed discount, fixed total, per-line override and complimentary-service prices are approved package policies. Use integer-cent allocations with exact line totals and a common backend resolver. Missing product prices are errors, never free products.
5. Vehicle eligibility is explicit, reviewed, and backed by source records/evidence. Existing selectable vehicle configurations are not proof of product fitment. Unverified candidates stay draft. Universal eligibility requires deliberate approval.
6. Category/product/service triggers are managed data. Existing legacy identities remain recorded in a migration map. Curated published definitions take precedence over equivalent legacy suggestions; no delete-first migration.
7. Saved quotes retain immutable package revision, quantities, base/effective prices, savings, tax and line-label snapshots. Future package edits do not recalculate old documents. Explicit repricing is a separate action with old/new amounts and history.
8. CMS writes and public package reads go through the backend. Database writes use service-role-only, invoker RPCs with explicit active-admin actor checks; no public CMS grants. Public requests never supply approved prices.
